# Fake Sort v1

[English](README.md)

[실행기](demo/index.html) · [시각화](demo/visualizer.html) · [기술 문서(영어)](docs/technical.md) · [벤치마크](benchmarks/README.md) · [테스트](tests/README.md)

Fake Sort(페이크 정렬)는 숫자 배열을 연속된 방으로 분할하고, 미확정 원소는 두 버퍼를 교대하며 이동시키고, 확정된 구간은 최종 결과 배열에 고정하는 실험적 비교 정렬이다. 제자리 정렬이나 안정 정렬은 아니다.

## 작동 원리

1. A는 입력 및 최종 결과 배열, B는 보조 배열이다.
2. 방의 중앙 인덱스에 있는 값을 피벗으로 선택한다(중앙값이 아님).
3. 작은 값은 목적지 왼쪽부터, 큰 값은 오른쪽부터 기록한다.
4. 방의 스캔이 끝나면 A의 가운데 빈 구간을 피벗 값으로 채운다. 원소가 하나인 방도 A에 확정한다.
5. 미확정 자식 방만 처리하며 단계마다 읽기·쓰기 버퍼를 교대한다.

각 분할은 숫자 값의 다중집합을 보존하고 서로 겹치지 않는 더 작은 자식 방을 만든다. 따라서 종료하며, 귀납적으로 A에 오름차순 결과가 만들어진다. 동일 키 레코드의 순서와 부호 있는 0의 구분은 보장하지 않는다.

## 실행 모드

| 모드 | JS 옵션 | C++ 번호 | 특징 |
|---|---|---:|---|
| Original | `original` | 0 | 기본 순차 파동 분할 |
| Pure | `pure` | 5 | D0, E1, BD; C8 제외 |
| Advanced | `advanced` | 1 | D0, C8, E1, BD |
| Optimized | `optimized` | 2 | Advanced + 방 목록 재사용 |
| Wave | — | 3 | Advanced 분할 코어, OpenMP 파동 병렬 처리 |
| Async | — | 4 | Advanced 분할 코어, OpenMP 방 단위 작업 |

- D0: 자식 방이 부모의 7/8을 초과하면 다음 피벗을 1/4 인덱스에서 선택한다.
- C8: 원소 2~8개 방에 정렬 네트워크를 적용한다.
- E1: 이미 A에 있고 모든 값이 같은 방의 재기록을 생략한다.
- BD: 피벗 인덱스까지 순방향, 끝에서부터 역방향으로 스캔하며 두 번째 스캔의 비교 순서를 반대로 한다. 두 스레드가 아닌 순차 분할이다.

모든 JS 모드는 외부 보조 배열을 받을 수 있다. JS에서는 Optimized만 방 목록을 재사용한다. C++ Optimized와 Pure는 호출 내부에서 방 목록을 재사용하며 공개 C++ API는 자체 보조 배열을 할당한다. Async의 기본 작업 임계값은 2048개이며 더 작은 자식 방은 로컬에서 처리한다.

## 복잡도

| 경우 | 시간 |
|---|---|
| 최선(모두 동일) | Θ(N) |
| 균형 분할 / 통상 무작위 입력 가정 | Θ(N log N) |
| 최악 | Θ(N²) |
| 추가 공간 | O(N) |

D0는 이차 시간의 최악 복잡도를 제거하지 않는다. 병렬 모드에서도 최초 큰 방의 분할은 순차적이다. 작은 입력이나 불균형 입력에서는 작업 관리, 할당, 추가 메모리 비용이 이점을 상쇄할 수 있다.

## JavaScript

최신 JavaScript 실행 환경이 필요하며 CommonJS 내보내기를 제공한다. 저장소 루트에서:

```js
const { fakeSort } = require('./src/FakeSort.js');
const a = [3, 1, 2, 1];
fakeSort(a, { mode: 'pure' });
console.log(a); // [1, 1, 2, 3]
```

`fakeSort(a, {mode = 'optimized', scratch = null} = {})`는 `a`를 수정하고 반환한다. 유한한 숫자가 담긴 쓰기 가능한 일반 밀집 `Array` 또는 `Float64Array`를 사용한다. 선택적 보조 배열도 쓰기 가능해야 하며 두 지원 타입 중 하나이고 입력 길이 이상이어야 한다. 입력 자체이거나 타입 배열의 동일한 기반 버퍼를 공유하면 안 된다. 동결된 보조 배열은 확실히 거부되지 않으며 원소가 두 개 미만이면 보조 배열 검사가 생략된다. NaN과 무한대는 거부한다.

## C++

C++17과 OpenMP가 필요하다. 저장소 루트에서 내장 자체 테스트를 빌드하고 실행한다.

```sh
g++ -O3 -std=c++17 -fopenmp src/FakeSort.cpp -o fake_sort
./fake_sort
```

프로그램에서 구현을 사용하려면 소스를 포함하기 전에 `FAKE_SORT_LIBRARY`를 정의해 자체 테스트 main을 제외한다.

```cpp
#define FAKE_SORT_LIBRARY
#include "src/FakeSort.cpp"
int main() {
    std::vector<double> a{3, 1, 2, 1};
    fake_sort(a, 5);
}
```

`fake_sort(a, mode=2, threads=4, cutoff=2048)`는 보조 공간을 사용해 입력 벡터의 유한한 double 값을 정렬한다. 스레드 수는 양수, 임계값은 2 이상이어야 한다. Wave는 검사 이후 임계값을 사용하지 않는다. 요청 스레드 수가 실제 동시 실행 수를 보장하지 않는다. Pure의 불균형 검사에는 부호 있는 `int` 곱셈이 사용되므로 보수적으로 `N <= INT_MAX / 8`(32비트 int에서 268,435,455)로 제한한다. 초대규모 입력은 검증하지 않았다.

## 검증

배포 검증 기록에는 JS 44,759건, C++ 63,297건의 검사 통과가 기록되어 있다. 중복 사례와 각각 11건/21건의 입력 거부 검사가 포함된다. JS는 Node.js 22.16.0, C++은 Linux의 GCC 14.2.0 및 OpenMP 환경에서 검사했다. 유한한 테스트 결과이며 데이터 경쟁 부재나 모든 입력의 정확성을 증명하지 않는다. JS 검사에서 부호 있는 0은 수치적으로 동일하게 취급한다.

```sh
node tests/test.js
g++ -O3 -std=c++17 -fopenmp tests/test.cpp -o test_cpp
./test_cpp
```

## 성능과 한계

기존 연구 측정에서는 일부 중복값·톱니 입력 및 병렬 작업에서 이점이 관찰되었다. 무작위, 정렬된 입력, 산·골 형태에서는 다른 구현이 더 빠를 수 있다. 기존 비교 결과는 특정 구현과 환경에 한정되며 이번 검증에서 새 성능 측정을 하지 않았다. 읽기 쉬운 JS 배포 구현은 연구용 벤치마크 코어와 동일한 속도를 보장하지 않는다. 하드웨어 카운터 측정, 데이터 경쟁 탐지 검사, 운영체제·브라우저 호환성 검증을 주장하지 않는다.

Fake Sort는 실험적 프로젝트이며 학술적 신규성, 특허성 또는 보편적인 우위를 주장하지 않는다.

ChatGPT는 알고리즘 논의, 최적화 제안, 반례 분석, 구현, 실험 및 문서 작성에 활용되었습니다.

연구 방향과 최종 설계 결정은 CrookedDirect가 주도했습니다. AI의 참여가 독립적인 학술 검증을 의미하지는 않습니다.
